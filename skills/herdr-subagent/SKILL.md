# Herdr Subagent

Herdr 可在独立 pane 中启动其他 CLI agent。Leader 负责切分任务、观察进度和复核结果。Herdr 命令、支持的 agent 和参数可能变化；每次先读取当前版本的 `herdr --skill` 与 `herdr agent start --help`。

## 判断是否委派

- 小改动、单文件任务和短问答由当前 agent 直接完成。
- 跨 CLI、独立审查、隔离工作树或长时间任务可以委派。
- 多条 lane 要改同一模块时，先确定共享接口和文件所有权。
- 任务需要额外 tab、工作树或资源时，先确认当前任务已授权这些操作。

## 启动 agent

- 1 到 2 个 agent 可使用当前 tab 中的相邻 pane。创建 3 个或更多 agent 时，使用专用 tab，并确认用户已同意。
- 将 `--cwd` 指向该任务的工作树。不要让 worker 在主工作树里并行写文件。
- 名称使用“职责-agent”格式，例如 `review-codex` 或 `docs-claude`。
- 先检查帮助，再传入 pane、工作目录和 agent 参数。模型选项放在 `--` 之后。
- 启动后确认 agent 已收到任务，并且处于工作状态。

## 写清任务边界

每个 prompt 都说明：

- 需求和要阅读的任务文档。
- 可修改的文件和禁止触碰的文件。
- 共享类型、接口或数据格式。
- 项目阶段对应的验收要求。
- 汇报内容和产物位置。

除非任务明确授权，要求 worker 不提交、不暂存、不重置、不切换分支。共享服务、构建产物和数据库由 leader 单独操作。不要把凭据、Cookie、客户数据或与任务无关的文件传给 worker。

## 等待进度

- 优先使用 Herdr 事件等待，并为每个 agent 跟踪独立状态。
- 启动前查看对应 agent 集成是否已安装。若缺少集成，按当前帮助安装；新 hook 通常只对新会话生效。
- 没有可用事件时，查看 pane 或日志。不要用长时间前台等待代替状态检查。
- `unknown` 不代表完成。提示超时也不证明任务没有送达。重发前先读 agent 最近的会话输出。

## 复核结果

不要只凭“完成”两个字验收。Leader 需要：

- 读 worker 的汇报并查看实际 diff。
- 按项目要求重新运行相关检查，确认检查覆盖的是新改动。
- 检查 UI、脚本、配置和文档的真实行为；没有执行的检查标为未验证。
- 将 worker 的产出与用户原始要求逐项核对。
- 确认后再按项目流程提交、推送或发布。

## 清理

只关闭本任务启动的 pane 和 tab。关闭前确认 agent 已空闲，且输出已保存。保留仍会用于后续修改或验证的 pane，并说明原因。
